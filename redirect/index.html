        Syntax reference

        socat · Linux 
        socat TCP-LISTEN:<port>[,bind=<addr>][,fork][,reuseaddr] TCP:<host>:<port>
        socat TCP-LISTEN:8080,fork,reuseaddr TCP:10.0.0.50:8080

        Listens on <port> and relays each connection on to <host>:<port>. Without bind= it listens on every interface. The target is resolved on the host running socat.

        ncat · Linux 
        ncat -l [<addr>] <port> --sh-exec "ncat <host> <port>"
        ncat -l 8080 --sh-exec "ncat 10.0.0.50 8080"

        Ncat (from nmap) listens, then runs a second ncat that dials the target, stitching the two together. ncat -z <host> <port> just tests a port.

        netsh portproxy · Windows 
        netsh interface portproxy add v4tov4 listenport=<p> [listenaddress=<addr>] connectport=<p> connectaddress=<host>
        netsh interface portproxy add v4tov4 listenport=8080 connectport=3000 connectaddress=172.16.0.50

        Adds a persistent proxy rule. listenaddress defaults to 0.0.0.0. show all lists rules; delete v4tov4 listenport=<p> removes one.

        nc + named pipe · Linux 
        mkfifo <pipe>
nc -l <port> < <pipe> | nc <host> <port> > <pipe>
        mkfifo /tmp/relay
nc -l 8080 < /tmp/relay | nc 10.0.0.50 8080 > /tmp/relay

        Plain nc can't relay on its own. The shell pipe carries the request one way; the named pipe loops the reply back, so the session works both ways. Drop the fifo and it's forward-only — a common mistake, and a reason people reach for ncat or socat.
